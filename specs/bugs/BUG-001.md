## Evidence and scope

CCEngine::emitCc sends on the stored MIDI channel (0 means accept all incoming,
transmit on 1). setState restores that channel, but no editor calls setMidiChannel.
Preset SysEx is channel-independent. This is a possible explanation for the operator's
working preset loads and non-working sliders, not a hardware-confirmed diagnosis.

## Fix plan

Add a compact channel selector to the controls MENU, offering 1–16 and the existing
Omni mode (explicitly labelled as output channel 1). Use the existing engine setter
and persistence; do not change synth settings or send a burst of CCs when selecting.
Keep the control synchronised when a host restores state while the editor is open.

## Verification

Use an isolated engine and a real selector (no processor or hardware ports): select
channel 5, emit CC 74, assert the sink receives channel 5; restore state to 12, assert
the selector follows and subsequent CC uses 12. Verify Omni sends on 1, saved channel
round-trips, and changing the selector alone emits nothing. Build VST3/Standalone,
run ctest, validate moduleinfo.json and macOS signatures. Hardware validation remains
with the operator; no device writes or automatic preset audition during testing.

## Result

Added MidiChannelSelector to ParamPanel's MENU above the volume controls. An
engine change notification keeps it synchronised after state restore or external
channel changes. The regression test first failed with `FAIL external engine
channel changes update the selector`; it passes after the setter notification fix.
All 12 CTest entries pass; VST3 and Standalone build. The selector/sink tests use
no hardware. No claim is made that the operator's slider issue is hardware-verified.
